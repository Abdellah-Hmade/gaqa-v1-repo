# GAQA v1 — Data-creation pipeline (original scripts)

These are the **dataset-generation scripts** used to build the GAQA v1 dataset.
The Zenodo release (10.5281/zenodo.21762025) is the authoritative dataset; these
scripts let you rebuild it from raw sequencing reads.

## Files

```
scripts/realval_pipeline.sh      idempotent stages: setup, download, subsample,
                                 assemble, qc (and knowledge + eval)
scripts/realval_v3_conditions.py generates conditions.csv (C01–C11 matrix)
src/build_gaqa_dataset.py        question rendering + metric generation helpers
src/build_realval_dataset.py     QUAST/BUSCO/CheckM parsers + corpus loader
src/build_gaqa_dataset_v3.py     main builder: label + render + jitter + splits
                                 -> data/processed_gaqa_v3 + realval_v3_heldout
src/build_v3_manifest.py         ENA/RefSeq manifest (12 organisms) -> manifest.csv
src/chunk_knowledge_sources.py   80 CC-BY docs -> ~300-token chunks (693)
src/generate_knowledge_qa.py     Qwen2.5-32B MCQ generation + verification + split
env/realval.yml                  conda/micromamba env for the bioinformatics tools
docs/gaqa_realval_run.md         original run documentation
data/realval/manifest.csv        seed manifest (full one regenerated by build_v3_manifest.py)
```

## Prerequisites

### 1. micromamba (required — creates the toolchain environment)

The pipeline's bioinformatics tools are installed through a micromamba/conda
environment (`env/realval.yml`). If you don't have micromamba yet, install it
with one of the following:

**Linux / macOS — install script (recommended):**

```bash
"${SHELL}" <(curl -L micro.mamba.pm/install.sh)
# prints the path to the installed binary; add it to your PATH, e.g.:
export PATH="$HOME/.local/bin:$PATH"      # adjust to the printed location
micromamba --version
```

**Linux / macOS — direct binary (no shell script):**

```bash
curl -Ls https://micro.mamba.pm/api/micromamba/linux-64/latest | tar -xvj bin/micromamba
mv bin/micromamba "$HOME/.local/bin/"     # make sure $HOME/.local/bin is on PATH
micromamba --version
```

**Windows (PowerShell):**

```powershell
Invoke-Expression ((Invoke-WebRequest -Uri https://micro.mamba.pm/install.ps1).Content)
```

**Already have conda/mamba?** Add micromamba to the base env instead:

```bash
conda install -n base -c conda-forge micromamba
```

Initialize the shell (so `micromamba activate` works) if prompted by the
installer, or run `micromamba shell init -s bash -p ~/micromamba` yourself.

### 2. Bioinformatics toolchain (installed by `env/realval.yml`)

The environment provides: **SPAdes** (≥3.15), **MEGAHIT** (≥1.2.9), **Flye**
(≥2.9), **QUAST** (≥5.0.2), **BUSCO** (≥5.4.0), **CheckM** (≥1.2.0), **seqtk**
(≥1.3), **seqkit** (≥2.3.0), GNU **parallel**, **wget**, **bc**, and Python 3.10
+ numpy.

> **CheckM database download:** the `checkm-genome` package's install script
> auto-downloads the CheckM reference DB (~275 MB) from Zenodo during
> `micromamba create`. This URL can be slow or return HTTP 504, which makes env
> creation appear to hang with no error. If it hangs, pre-download the tarball
> and set `CHECKM_DATA_PATH` to it, then re-run the create:
>
> ```bash
> wget -O checkm_data_2015_01_16.tar.gz \
>   "https://data.ace.uq.edu.au/public/CheckM_databases/checkm_data_2015_01_16.tar.gz"
> export CHECKM_DATA_PATH="$PWD/checkm_data_2015_01_16.tar.gz"
> micromamba create -f data_pipeline/env/realval.yml
> ```
>
> The pipeline's `setup` stage also performs its own CheckM DB download, so this
> step is only about getting through `micromamba create` cleanly.

### 3. Network / optional services

- **ENA / RefSeq access** — `build_v3_manifest.py` and the download stage fetch
  genomes and raw reads from ENA (EBI) and NCBI. An internet connection is
  required; the manifest step verifies every URL with an HTTP HEAD request.
- **Knowledge QA generation** — `generate_knowledge_qa.py` needs a vLLM endpoint
  serving `Qwen2.5-32B-Instruct`; set `KNOWLEDGE_ENDPOINT` in the top-level
  `.env` (default `http://localhost:8000/v1`). This stage is optional — the
  released dataset already includes the knowledge splits.

### 4. Disk space

The rebuild is large. Budget at least **30–50 GB** of free space:

| Artifact | Approximate size |
|---|---|
| `realval` env (installed) | ~3.4 GB |
| CheckM DB + BUSCO lineage | ~0.5 GB |
| Raw reads + references (12 organisms) | 10–25 GB |
| Subsampled reads (11 conditions/org) | 5–15 GB |
| SPAdes/MEGAHIT assemblies (132) | 5–15 GB |

> Note: `scripts/rebuild_data.sh` **bootstraps micromamba automatically** if it
> is not found on PATH (into `data_pipeline/tools/micromamba/`). Installing it
> yourself per step 1 is still recommended so the standalone `Usage` commands
> below work — after installing, run `micromamba shell init` (or `export PATH`)
> so `micromamba` is on your PATH.

## Usage

The simplest path is the one-shot orchestrator (does manifest → download →
conditions → assemble → QC → build; see `scripts/rebuild_data.sh`):

```bash
bash scripts/rebuild_data.sh
```

Or run the stages manually (single data dir `data_pipeline/data/realval_v3/`):

```bash
# 1. environment (bioinformatics toolchain)
micromamba create -f data_pipeline/env/realval.yml
micromamba activate realval

# 2. manifest (12 organisms) -> manifest.csv + manifest_pipeline.csv
python data_pipeline/src/build_v3_manifest.py

# 3. download reads + references
REALVAL_DATA_DIR=data_pipeline/data/realval_v3 \
  bash data_pipeline/scripts/realval_pipeline.sh --stage download

# 4. condition matrix (C01–C11 per organism) -> conditions.csv + subsampled/
python data_pipeline/scripts/realval_v3_conditions.py \
  --data-dir data_pipeline/data/realval_v3 --runner "micromamba run -n realval"

# 5. assemble + QC
REALVAL_DATA_DIR=data_pipeline/data/realval_v3 \
  bash data_pipeline/scripts/realval_pipeline.sh --stage assemble --stage qc

# 6. build the GAQA dataset (label + render + jitter + splits)
python -m src.build_gaqa_dataset_v3 --data-dir data/realval_v3 \
  --include-knowledge     # run from data_pipeline/ (src is a package)
```

Notes:
- The builder runs as `python -m src.build_gaqa_dataset_v3` **from the
  `data_pipeline/` directory** (the `src/` package + `ROOT` paths assume it).
- The download stage reads `manifest_pipeline.csv` (pipeline format); the
  conditions/builder read `manifest.csv` (v3 format) — both are emitted by
  `build_v3_manifest.py`.
- Jitter: `--jitter 60 --jitter-mag 0.10` (default) → 60 copies per condition;
  heldout questions are unjittered.
- Expect ~79 surviving training conditions (failed assemblies are dropped) →
  train ≈ 4,740 qc + 4,740 remediation + 159 tool_selection; plus knowledge
  (1,404 train / 100 val / 181 test) merged via `--include-knowledge`.
